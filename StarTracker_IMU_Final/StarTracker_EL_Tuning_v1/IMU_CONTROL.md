# 기존 MPU6050 기반 EL 폐루프 제어

추가 엔코더 없이 기존 하드웨어로 EL(ALT) 목표각을 제어하는 버전입니다.
기본 실행 설정은 `IMU_TRACKING_ENABLED=True`, `ENCODER_ENABLED=False`입니다.
필터 기본값은 `IMU_FILTER_MODE="kalman"`이며 각도와 자이로 바이어스를 함께 추정합니다.
칼만 모델·Q/R 설정·시작 보정은 [KALMAN_FILTER.md](KALMAN_FILTER.md)를 참고하세요.
아래쪽 MPU6050은 기존 시작 정렬에, 상부 MPU6050은 시작 정렬과 연속 EL 측정에
사용합니다. 모터 핀·기어비·촬영·BLE 설정은 그대로 둡니다.

## 무엇이 바뀌었나

```text
천체 RA/Dec → 기존 천문 계산 → 목표 ALT / AZ
                                │       │
           상부 IMU → 칼만 → EL PID     기존 AZ 스텝 제어
                                │       │
                                TMC2209
                                   ↓
                                 실제 축

기존 Plate Solving → EL 좌표 기준 오프셋 및 AZ 추정 위치 보정
```

- 정렬 완료 후 IMU 버스를 닫지 않고 프로그램 종료 시 닫습니다.
- 가속도·자이로를 14바이트 연속 읽기하고, 가속도 Y/Z 기울기와 자이로 X를
  칼만 필터에 넣습니다. 정렬용 11회 샘플 대기를 추적에 쓰지 않습니다.
- 초기 정렬 후 약 1.25초간 정지 상태에서 자이로 바이어스를 측정합니다.
- EL은 측정값으로 갱신합니다. 명령한 스텝을 실제 EL 이동량으로 더하지 않습니다.
- PID 출력(°/s)을 제한된 STEP 명령으로 바꾸며, 소수 스텝을 이월합니다.
- AZ는 기존 스텝 추정입니다. 자이로 적분으로 AZ 절대방위를 만들지 않습니다.
- 카메라 보정은 IMU 좌표의 오프셋으로 유지되어 다음 센서 읽기에도 남습니다.
- 센서 오류 후 모터를 정지시키고 세션 종료 시 수동 모드로 자동 재가동하지 않습니다.

현재 필터는 **EL 각도·자이로 바이어스를 추정하는 2상태 칼만 필터**입니다.
이전 저역통과 방식은 `IMU_FILTER_MODE="lowpass"`로 비교할 수 있습니다.
느린 1축 회전 모델이며 3차원 AHRS나 Compass 융합은 아닙니다.
필터 추가만으로 장노출 정밀도가 보장되지는 않습니다.

## 실행

PC에서 하드웨어 없이:

```console
python simulate_imu_control.py
```

`data/kalman_demo/report.html`을 브라우저에서 열면 목표 EL과 추정 EL, 오차를 봅니다.
같은 폴더의 `imu_control.csv`와 `summary.json`에 원자료·조건을 저장합니다.
AZ 그래프는 **센서 측정이 아닌 스텝 추정**이라고 표시합니다.
가속도계 각도/추정각, 자이로 회전속도/바이어스, 칼만 잔차도 표시합니다.

Raspberry Pi에서는 기존 패키지·배선 환경에서 기존과 같이:

```console
python main.py
```

기존 초기 정렬 및 목표 촬영/Plate Solving 후 추적 중 EL PID가 동작합니다.
`Gyro calibration: keep the mount still` 메시지가 나오면 마운트를 움직이지 마세요.
이번 작업에서는 Pi·센서·모터를 실제로 구동하지 않았습니다.
기존 검증된 GPIO 환경을 사용하고, 첫 구동은 작은 이동으로 방향부터 확인하세요.

실제 추적 로그는 `data/logs/imu_control_시각.csv`입니다.

```console
python -m services.control_telemetry data/logs/imu_control_시각.csv data/logs/imu_report.html --imu
python -m unittest discover -s tests -v
```

CSV의 `actual_alt`는 기준 보정·필터 후 IMU EL, `actual_az`는 스텝 추정입니다.
`speed_az`는 해당 주기의 스텝 명령을 시간으로 나눈 값이며 실제 속도 측정이 아닙니다.
정렬·수동 이동은 추적 CSV에 포함되지 않습니다.
칼만 모드에서는 `accel_alt`, `gyro_rate`, `gyro_bias`, `innovation_deg`,
`angle_variance`, `kalman_gain` 진단값도 기록합니다.

## 설정과 튜닝

| `config.py` 설정 | 기본값 / 의미 |
| --- | --- |
| `IMU_TRACKING_ENABLED` | True: 연속 EL 제어, False: 기존 초기 정렬만 |
| `IMU_TRACKING_PID` | Kp=0.8, Ki=Kd=0, 속도 0.10°/s, 가속도 0.20°/s², 허용오차 0.15° |
| `IMU_TRACKING_FILTER_TAU` | 0.25s, `lowpass` 모드에서만 사용 |
| `IMU_TRACKING_MAX_READ_SECONDS` | 0.15s 초과 읽기/오래된 데이터 거부 |
| `IMU_TRACKING_MAX_GAP` | 제어 주기 0.5s 초과 시 정지 |
| `IMU_TRACKING_MIN/MAX_GRAVITY_G` | 0.75–1.25g 범위 검사 |
| `IMU_TRACKING_MAX_JUMP_DEG` | 연속 샘플 5° 급변 시 정지 |
| `IMU_TRACKING_STALL_*` | 8s, 누적 명령 0.30°, 관측 움직임 0.05° 기준 |

PID 구조지만 기본은 P 제어입니다. 이 값은 실물에서 튜닝하지 않은 초기값입니다.
허용오차 0.15°는 **요구 정확도나 센서 정확도 사양이 아닙니다**.
작은 목표각 변경으로 진동과 지연을 측정한 다음 Kp/필터/허용오차를 조절하세요.
I/D는 필요한 경우에만 추가합니다. 기존 50ms 주기·최대 5스텝 제한을 유지하므로
큰 각도의 이동은 느립니다. 데드밴드나 정지에서 속도 명령을 즉시 0으로 만들며,
가속도 제한은 이동 명령 중 적용합니다.

## 좌표와 설치 조건

상부 센서 Y/Z로 기울기가 증가하는 방향과 실제 EL 증가 방향이 맞아야 합니다.
기존 IMU 방향 probe 결과를 모터의 전기적 DIR 극성에 적용합니다. 처음부터
정렬되어 probe가 생략되면 `MOTOR_ALT_POSITIVE_DIRECTION` 설정을 사용합니다.

초기 정렬 위치를 EL=0으로 참조하고, 첫 Plate Solving이 실제 하늘 고도에
맞춰 오프셋을 다시 잡습니다. 베이스의 pitch를 매 순간 빼는 구조는 아닙니다.
AZ가 회전하면 두 센서 좌표계가 달라질 수 있기 때문입니다. 마운트 베이스는
가능한 수평으로 두고, 센서가 축에 맞게 단단히 고정되어야 합니다.
이 단순 1축 모델은 베이스 기울기·축 비직교·카메라 장착 오차를 완전 보정하지 않습니다.

수동 조작은 목표각을 유지하는 PID가 아니라 IMU EL을 읽어 짧게 조그 이동합니다.
EL에는 `MANUAL_MIN/MAX_ALTITUDE` 소프트 제한을 적용합니다.
추적 중에는 노이즈를 고려해 한계 밖 1° 초과에서 오류를 내며, 이동 명령은
측정각으로 계산한 기존 ALT 범위 안으로 제한합니다. 필터 지연 때문에
소프트 제한은 물리적 리미트 스위치와 동등하지 않습니다.

## 실패와 성능 한계

I²C 오류·지연, NaN/Inf, 중력 크기 이상, 관측 불가능한 Y/Z 투영,
급격한 각도 변화, 주기 초과, EL 범위 이탈, 명령 대비 무응답은 정지 원인입니다.
오류 후에는 센서·배선을 확인하고 프로그램을 재시작하여 정렬해야 합니다.
엔코더나 스텝 추정값으로 EL을 자동 대체하지 않습니다.

중력 크기 검사는 모든 진동·선형가속도 영향을 제거하지 못합니다. 값이 그럴듯하게
고정된 센서 실패도 즉시 알아낼 수 없으며, 무응답 검사는 조건을 만족한 뒤 작동합니다.
Python/I²C 호출은 하드 실시간이 아니고, 읽기 시간 검사는 호출이 반환된 뒤
판단합니다. 실제 정밀도, 진동, CPU 부하, 긴 노출에서의 별상은 실물로 확인해야 합니다.
AZ에는 여전히 스텝 손실과 백래시가 남으며, 카메라 보정 간격 사이의 AZ 오차를
IMU로 관측하지 않습니다. 케이블 감김·하드웨어 리미트·시야 회전 보정은 추가하지 않았습니다.

## 검증

2026-10-12, 하드웨어 없는 **전체 테스트 114개 통과**.
기존 97개에 칼만 수학·자이로 입력·시작 보정·제어 연결 테스트 17개를 추가했습니다.
기존 정렬 전용 모드·엔코더 모드·촬영·세션 테스트도 함께 통과했습니다.
Windows asyncio 로컬 소켓의 샌드박스 제약 때문에 전체 테스트는 동일한
로컬 코드로 샌드박스 밖에서 실행했습니다.

80초 시뮬레이션은 모터 응답 85%, ±0.02° 결정적 측정 잡음,
30초의 EL −0.7° 외란을 사용했습니다. 칼만 모드에는 자이로 바이어스 0.12°/s와
작은 자이로 잡음도 포함합니다. 종료 시 추정각 오차 약 0.148°,
시뮬레이션 내부 실제축 오차 약 0.145°로 0.15° 데드밴드 안에 복귀했습니다.
이 결과는 실물 측정이 아니며, 실제 백래시·장착 오차·GPIO 지터를 포함하지 않습니다.
HTML 생성은 확인했지만 실제 브라우저 렌더링은 시각 검증하지 않았습니다.
